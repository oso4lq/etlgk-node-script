# download-speed-cli

Консольный скрипт на Node.js. Принимает ссылку на файл, 10 раз подряд полностью его скачивает и показывает, сколько времени занял каждый запрос, сколько данных получено и с какой скоростью шла загрузка.

## Требования

- Node.js 20 или новее.
- Устанавливать ничего не нужно: зависимостей нет, используется только стандартная библиотека Node.js.

## Запуск

```bash
node index.js                 # спросит ссылку; Enter — файл по умолчанию из ТЗ
node index.js "<ссылка>"      # ссылка аргументом
npm start                     # то же, что node index.js
```

Ссылку с символом `&` обязательно берите в кавычки, иначе оболочка её обрежет.

| Флаг | Что делает |
|------|------------|
| `-c`, `--count N` | Сколько запросов сделать, от 1 до 1000. По умолчанию 10. |
| `-y`, `--yes` | Не спрашивать подтверждение для файлов неизвестного формата. |
| `-h`, `--help` | Показать справку. |

Файл по умолчанию — видео из ТЗ (28,52 MB):
`https://drive.usercontent.google.com/download?id=1Pk2Gk1l2TODrjQO0xxaAAfvZCJ9khqVR&export=download`

## Что и как измеряется

- **Время запроса** — от отправки запроса до получения последнего байта ответа. В него входят установка соединения, ожидание сервера и запись на диск.
- **Среднее время запроса** — сумма времени успешных запросов, делённая на их число. Рядом показаны минимум и максимум: первый запрос обычно медленнее остальных, потому что открывает соединение (DNS, TLS), а следующие его переиспользуют.
- **Общий объём** — сумма байт, записанных на диск по всем успешным запросам.
- **Скорость скачивания** — общий объём, делённый на суммарное время успешных запросов.
- **Текущая скорость** в строке прогресса считается за последнюю секунду.

### Единицы

| Величина | Единицы |
|----------|---------|
| Объём | `B`, `KB`, `MB`, `GB`, `TB` |
| Скорость | `B/s`, `KB/s`, `MB/s`, `GB/s`, `TB/s` |
| Время | `мс`, `с`, `мин` |

Единица подбирается автоматически по величине значения. Множитель двоичный: 1 KB = 1024 B, 1 MB = 1024 KB и так далее. Скорость — это байты в секунду (не биты): 1 MB/s = 8,39 Мбит/с.

Запросы, завершившиеся ошибкой, и паузы перед повторами в расчёт времени и скорости не входят.

## Куда сохраняются файлы

```
downloads/
  2026-11-18 15-41-57/        ← папка одного запуска (местное время)
    01_имя файла.mp4
    02_имя файла.mp4
    ...
    10_имя файла.mp4
```

- Папка `downloads` создаётся в каталоге, из которого запущен скрипт.
- Номер в начале имени не даёт копиям перезаписать друг друга.
- Имя файла берётся из заголовка ответа, а если его нет — из ссылки. В имени остаются латиница, кириллица, цифры, пробел и символы `. _ - ( )`; всё остальное заменяется на `_`.
- В конце скрипт предлагает удалить папку запуска. Удаляется только она; `downloads` остаётся.

## Проверки перед загрузкой

Скрипт сначала убеждается, что по ссылке действительно лежит файл, и определяет его формат по расширению и типу содержимого.

| Формат | Что происходит |
|--------|----------------|
| Безопасный: видео, аудио, изображения, документы, текст, архивы | Скачивается. |
| Исполняемый: `exe msi bat cmd com scr ps1 vbs js jar sh apk dmg pkg deb rpm dll lnk` | Не скачивается. |
| Любой другой | Предупреждение и вопрос «Всё равно скачать? (y/N)». |

Кроме того, проверяются первые байты содержимого. Если файл назван `video.mp4`, а внутри исполняемый код (Windows PE, ELF, Mach-O, скрипт с `#!`), загрузка отменяется и файл удаляется.

Это защита от очевидных случаев, а не антивирус: архив или документ с вредоносным содержимым она не распознает.

## Ошибки и обрывы

- **Невалидная ссылка** (не http/https, файл не найден, нет доступа, вместо файла веб-страница) — сообщение и выход, ничего не скачивается.
- **Временные сбои** (обрыв соединения, ошибки 5xx и 429, файл получен не полностью, сервер 30 секунд не присылает данные) — до трёх повторов запроса с паузами 1, 2 и 4 секунды.
- **Постоянные ошибки** (например, 404 посреди запуска) — запуск останавливается, печатается итог по успешным запросам.
- **Ctrl+C** — недокачанный файл удаляется, печатается итог по завершённым запросам. Повторное нажатие завершает скрипт немедленно.
- Недокачанные файлы на диске не остаются: данные пишутся во временный файл `*.part`, который получает настоящее имя только после проверки размера.
- Если вывод перенаправлен в файл (`node index.js > log.txt`), строка прогресса и цвета отключаются, вопросы не задаются.

Коды выхода: `0` — успех, `1` — ошибка, `130` — прервано пользователем.

## Тесты

```bash
npm test
```

Тесты не обращаются к интернету: сетевые сценарии (обрыв, зависание, ошибки сервера, страница подтверждения Drive) воспроизводятся на локальном сервере.

## Структура

```
index.js           точка входа: аргументы, Ctrl+C, код выхода
lib/app.js         сценарий запуска по этапам
lib/cli.js         разбор аргументов
lib/url.js         проверка ссылки, приведение ссылок Google Drive
lib/download.js    проверка ссылки запросом, загрузка с замером, повторы
lib/safety.js      классификация форматов, сигнатуры исполняемых файлов
lib/filename.js    имена файлов и папки запуска
lib/rundir.js      создание и удаление папки запуска
lib/stats.js       итоги и текущая скорость
lib/format.js      единицы измерения
lib/ui.js          этапы, прогресс, таблица, вопросы
test/              тесты
```
